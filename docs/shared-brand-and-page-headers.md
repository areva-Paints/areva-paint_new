# Shared public headers and Areva logo

Public page banners use `public/assets/page-gradient.css` for the reference purple/pink/orange gradient, responsive Georgia headings, copy sizes and aligned inner containers. Home and Products retain their existing banner styles. Gallery, Explore Areva, tools, support pages and Warranty Registration share these styles in both the reference website and React Studio. Reference sections that begin with a banner remove the original section top padding, so navigation meets the banner directly on desktop and mobile.

`BrandLogo` uses the official `/assets/images/areva-brand-logo.png` artwork in public navigation, Warranty Registration, admin sign-in and every admin sidebar tab. `public/assets/brand.css` keeps its proportions and dimensions consistent (112 × 84 desktop, 96 × 72 mobile). Every admin tab, editor dialog, warranty details dialog and the sign-in artwork reuse the same gradient token. The admin page banner starts at the top of the main workspace, with white text and readable action buttons; forms and tables retain light backgrounds. Private warranty PDFs already use the same artwork.

The redundant white utility bar and administration/section breadcrumb have been removed. Website and logout actions remain in the sidebar, including its mobile layout. The sidebar uses a lavender/pink/peach background, tinted navigation cards and coloured icons, with a purple selected tab and visible keyboard focus. Desktop scrolling and the mobile navigation grid remain available, and the logo keeps its standard dimensions. The banner meets the top edge on desktop and sits directly below mobile navigation without an extra strip.

Warranty fields now pair **Purchase invoice number** with **Date of purchase**. The login mobile snapshot is described in [the warranty guide](warranty-registration.md). Existing SQL installations after migration 010 use [011-warranty-login-mobile.sql](../database/migrations/011-warranty-login-mobile.sql); the live runtime continues to use its private JSON store. No live migration is performed by this code change.
