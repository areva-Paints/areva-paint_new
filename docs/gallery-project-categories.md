# Gallery design and project categories

The public Gallery uses the supplied design: a purple-to-orange header, centered pill tabs, a highlighted selected tab and image-first project cards on a pale background. Tabs are **Projects**, **Ads & Campaigns** and **Customer Reviews**. Projects is selected by default. The Projects heading is **Beautiful Spaces. Lasting Impressions.**, followed by **Explore how colour, texture and protection can transform every surface.**

Projects can be **Interior**, **Exterior**, **Textures**, **Waterproofing**, **Commercial** or **Other**. The All projects/category filters show counts and selected states, hide unrelated cards and show a helpful empty state when a category has no entries. A card displays the first photo as its cover, the category badge, title, optional description/location and album action. Clicking a filtered card still opens that project's complete album, including captions, thumbnails and keyboard controls. Ads and customer reviews retain their existing content and functionality.

Use **Admin → Gallery → Projects** to add or edit a project. Set its category, name, optional description and location, then upload up to 20 photos (25 MiB each). The first photo is the card cover; existing **Use as cover** controls change it. The description appears below the title on the public card and in the album. Admin previews use the same image-above-text format with category badges, and can be searched by title, description, location or category, or filtered by category. **Save project to website** publishes immediately; applying to workspace uses the usual **Save changes** workflow. The other admin tabs use the same names as the public tabs.

Both the embedded reference website and React Studio use the same saved project category. Existing projects without one appear under **Other** until an admin assigns them; no category is guessed from an image/name. Existing photographs, captions, descriptions, timestamps and IDs are preserved. Old content stores receive a read-time default, and older clients omitting the category preserve the previously saved choice. Invalid category values are rejected. Changing category is a meaningful update, recorded in activity history and the project's server-managed update time; unchanged saves retain timestamps.

The runtime still persists `galleryProjects[]` to `CONTENT_DATA_DIR/content.json`, with the existing public upload store. No new database table is required. Fresh SQL adds `gallery_projects.category varchar(20) NOT NULL DEFAULT 'other'` with the matching allowed-value check and category/update index. Existing SQL installations after migration 009 use [010-gallery-project-categories.sql](../database/migrations/010-gallery-project-categories.sql) once. It supports `public` or private `areva`, stops on ambiguity, defaults old rows to Other and preserves row data/timestamps and access permissions. The table count stays 23. No live database was changed or connected.
